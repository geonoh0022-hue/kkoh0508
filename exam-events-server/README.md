# 시험기간 이벤트 — 서버 저장·학생 배포용

원본 HTML의 색상, 레이아웃, 탭, 시간표, 학년도별 관리 형식을 유지했습니다. 기록 저장은 브라우저 저장소에서 서버의 SQLite 데이터베이스로 변경했습니다. **이 폴더는 배포용 완성 소스이며, 아직 공개 서버에 배포된 상태는 아닙니다.**

## 달라진 점

- 교사 비밀번호로 로그인하면 명단·열품타·플래너·시험 로또·시험 안내를 관리합니다.
- 학생은 배포 주소와 개인 접속 코드로 로그인해 본인의 예상·실제 점수만 조회·제출합니다. 다른 학생의 이름과 점수는 학생 브라우저에 전달되지 않습니다.
- 교사 화면의 **학생에게 배포하기**에서 주소 복사와 전체·개별 코드 발급을 할 수 있습니다.
- 학생의 동시 제출은 각각 저장합니다. 교사가 오래된 화면에서 수정하면 기존 학생 제출을 덮어쓰지 않고 최신 기록을 다시 불러오도록 안내합니다.
- 제출 성공 표시는 서버 저장 응답 후에 나옵니다. 연결 오류 시 입력 내용을 유지합니다.
- 교사 화면은 사용자가 입력 중이 아닐 때 약 15초마다 최신 기록을 확인합니다.
- 기존 JSON 백업 불러오기와 기록 백업을 유지했습니다.

## 서버가 없을 때: Render에 배포

필요한 것: GitHub 계정과 Render 계정. 이 구성은 **유료 웹 서비스와 영구 디스크**를 사용합니다. 생성 화면의 요금을 확인하고 진행하세요. 무료·임시 저장소에 SQLite 파일을 두면 재시작·재배포 때 기록이 사라질 수 있습니다.

1. ZIP을 풀고 GitHub에 새 **비공개 저장소**를 만듭니다.
2. `exam-events-server` 폴더 안의 파일들을 저장소 최상위에 올립니다. 최상위에 `render.yaml`, `Dockerfile`, `server.py`, `public` 폴더가 보여야 합니다. 실제 기록, `.env`, 개인 코드는 올리지 않습니다.
3. [Render 대시보드](https://dashboard.render.com/)에서 **New → Blueprint**를 선택하고 위 저장소를 연결합니다.
4. `render.yaml` 설정을 확인합니다. 웹 서비스 1개, `/var/data` 영구 디스크 1GB가 지정되어 있습니다.
5. `ADMIN_PASSWORD`에 본인이 정한 **12자 이상 교사 비밀번호**를 입력합니다. 설정 파일에 비밀번호를 직접 적어 올리지 마세요.
6. 배포가 완료되면 Render가 제공한 HTTPS 주소를 엽니다. 주소 끝에 `/teacher`를 붙이면 교사 로그인입니다.
7. 교사 로그인 후 명단과 시험을 설정하고 아래 **학생에게 배포하기**를 엽니다.
8. 학생 접속 주소(`/student`)는 학급에 공유하고, 각 학생에게 **자기 코드만 개별 전달**합니다.

배포 주소 예시: `https://발급된주소/teacher` 및 `https://발급된주소/student`. 위 주소는 예시이며 실제 생성된 주소를 사용해야 합니다. HTML 파일을 더블클릭하거나 정적 파일만 업로드하는 방식으로는 서버 저장이 동작하지 않습니다.

설정 근거: [Render 영구 디스크](https://render.com/docs/disks), [Blueprint 설정](https://render.com/docs/blueprint-spec), [Docker 배포](https://render.com/docs/docker). 영구 데이터는 반드시 `DATA_DIR=/var/data` 및 해당 디스크를 유지해야 합니다. 이 구성은 서비스 인스턴스 1개를 사용합니다.

## 기존 기록 옮기기

1. 기존 HTML을 **기록을 입력했던 기기와 브라우저**에서 엽니다.
2. 기존 교사 잠금 해제 후 **기록 백업**으로 JSON 파일을 저장합니다.
3. 새 서버의 교사 화면에서 **백업 불러오기**로 해당 파일을 선택합니다.
4. **서버 저장 완료**가 표시되는지 확인한 뒤 학생 코드를 발급합니다.

원본 HTML 자체에는 브라우저에 입력한 기록이 포함되지 않을 수 있습니다. HTML만 복사하면 이전 기록이 자동 이전되지는 않습니다. 새 서버는 빈 명단으로 시작합니다.

## 학생·교사 사용 방법

**교사:** `/teacher` 접속 → 로그인 → 학년도·시험 선택 → 학생 명단 등록 → 시험 안내에 과목 추가 → 필요한 경우 예상 점수 입력 기간 지정 → 학생 코드 발급.

**학생:** `/student` 접속 → 받은 코드 입력 → 본인 이름 확인 → 예상 또는 실제 점수 입력 → 제출 → 서버 저장 완료 메시지 확인.

예상 점수는 40~100점, 실제 점수는 0~100점입니다. 예상 점수 입력 기간은 서버의 한국 시간으로 검사합니다. 실제 점수 입력은 원본처럼 기간 제한 없이 가능합니다. 열품타와 플래너는 교사 화면에서 관리합니다.

학생 코드는 로그인 비밀값입니다. 전체 코드 화면을 학급 단체방에 공유하지 마세요. 코드는 발급 직후에만 볼 수 있고 서버에는 해시만 저장합니다. 분실하면 해당 학생만 재발급합니다. 재발급하면 이전 코드와 해당 학생의 기존 로그인은 해제됩니다. 새 학년도에서는 새 명단으로 코드를 발급하세요.

로그인은 최대 8시간 유지됩니다. 공용 기기에서는 **로그아웃/관리 잠그기**를 누릅니다. 교사와 학생은 같은 브라우저에서 하나의 로그인 상태를 공유하므로 양쪽을 동시에 시험하려면 별도 브라우저나 시크릿 창을 사용하세요.

## 내 PC에서 확인하기 — Docker

Docker가 설치된 PC에서 이 폴더를 엽니다.

1. `.env.example`을 `.env`로 복사합니다.
2. `.env`의 `ADMIN_PASSWORD`를 본인만 아는 12자 이상 비밀번호로 바꿉니다.
3. 터미널에서 실행합니다.

```sh
docker compose up --build -d
```

교사 화면: `http://localhost:8080/teacher`

학생 화면: `http://localhost:8080/student`

로컬 주소는 내 PC 확인용이므로 학생에게 배포할 수 없습니다. 공개 사용은 위 Render 배포처럼 HTTPS 주소를 사용하세요. 로컬 테스트에서는 `COOKIE_SECURE=false`, 공개 HTTPS 서버에서는 반드시 `true`입니다. Docker의 `exam-data` 볼륨에 기록이 남습니다. `docker compose down -v`는 기록 볼륨까지 지우므로 사용하지 마세요.

## Python으로 직접 실행

Python 3.12 이상에서 사용할 수 있습니다. 예: Windows PowerShell.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:ADMIN_PASSWORD = '본인이 정한 12자 이상 비밀번호'
$env:COOKIE_SECURE = 'false'
.\.venv\Scripts\python.exe server.py
```

직접 공개 서버에 설치하는 경우 HTTPS 역방향 프록시를 앞에 두고 `COOKIE_SECURE=true`, 영구 `DATA_DIR`, 접근 제한 및 백업을 운영 환경에 맞게 설정합니다. 실행 서버는 [Waitress](https://docs.pylonsproject.org/projects/waitress/en/stable/usage.html)를 사용합니다.

## 백업과 비밀번호 관리

- **기록 백업**은 모든 학년도·시험 기록을 JSON으로 내보냅니다. 교사 비밀번호, 학생 코드, 로그인 상태는 포함하지 않습니다.
- 서버 전체 이전에는 영구 디스크의 SQLite 파일이 필요합니다. 실행 중인 DB 파일을 단순 복사하지 말고 서비스 중지 후 복사하거나 SQLite의 백업 기능을 사용하세요.
- 교사 비밀번호는 시험 로또 탭의 **비밀번호 변경**에서 바꿀 수 있습니다. 변경하면 다른 교사 로그인은 해제됩니다.
- `ADMIN_PASSWORD`는 빈 DB를 처음 만들 때만 적용됩니다. 나중에 환경변수만 바꿔도 기존 비밀번호는 바뀌지 않습니다.
- 비밀번호를 잊었다면 서버 콘솔에서 `python reset_password.py`를 실행하고 새 비밀번호를 입력합니다. 콘솔 접근이 가능한 서버 소유자만 사용하세요. 기록과 학생 코드는 유지됩니다.
- 서버 저장 오류가 나면 표시되는 **수정본 내려받기**로 보관한 다음 **최신 기록 다시 불러오기**를 누르세요. 다른 사람의 새 제출이 있다면 수정본 전체를 즉시 덮어씌우기보다 필요한 수정만 다시 반영하세요.

## 검증 범위

실행: `python -m unittest -v test_server.py`

인증·학생 간 조회 분리·권한 차단·동시 제출·오래된 교사 수정 차단·입력 기간·점수 검증·코드 재발급·비밀번호 변경·로그아웃·DB 재열기 후 기록 유지 테스트를 통과했습니다.

실제 브라우저에서도 교사 로그인, 명단·과목 등록, 코드 발급, 모바일 크기의 학생 입력, 저장 후 새로고침, 연결 실패 때 입력 유지, 교사 점수 확인을 점검했습니다. 원본 CSS는 그대로 유지했습니다.

공개 Render 배포, Docker 이미지 빌드, 실제 학생 계정 운영은 아직 실행하지 않았습니다. 배포 후 먼저 교사 1명·시험용 학생 2명으로 HTTPS 로그인·제출·재시작 후 기록 유지까지 확인하고 실제 배포하세요.
